# 4090 服务器部署配置（video-transcribe-platform）

> 面向已到位的 RTX 4090 服务器（24GB 显存）。本文是可照抄执行的部署配置；资源评估见 `4090-资源申请清单.md`。
> 最后更新：2026-10-14。

## 0. 前置检查（一次性）

```bash
# 1. 驱动（需 >= 550，支持 CUDA 12.x）
nvidia-smi
# 2. Docker
docker --version          # >= 24
# 3. NVIDIA Container Toolkit（缺则先装）
docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
```

任一步失败先解决再继续。内网无法访问外网时，驱动/镜像/模型全部走离线包（见 §5 离线部署）。

## 1. 目录规划

```text
/opt/plugin_parser/            # APP_ROOT = ASSET_ROOT
├── models/
│   ├── moss/OpenMOSS-Team/MOSS-Transcribe-Diarize/   # 1.8 GB
│   └── summary/Qwen3.5-4B-Q4_K_M.gguf                # 2.6 GB
├── deploy.env                 # 环境配置（chmod 600，不入库）
├── docker-compose.yml         # 仓库 deployment-assets/server/ 拷贝
├── docker-compose.gpu.yml     # GPU overlay（本次新增）
└── images/*.tar.gz            # 离线镜像（在线构建可省）
```

## 2. 需要传到服务器的文件

| 内容 | 体积 | 来源 |
|---|---|---|
| 代码仓库（或仅 deployment-assets/server/ + services/moss-transcriber/main.py + deploy/） | — | git / scp |
| models/moss/ 整目录 | 1.8 GB | 本地 `deployment-assets/models/moss` |
| models/summary/Qwen3.5-4B-Q4_K_M.gguf | 2.6 GB | 本地 `deployment-assets/models/summary` |
| 镜像 tar.gz（离线时） | moss≈10–15GB（GPU 版） | 本地构建导出，见 §3 方式 B |

```bash
scp -r deployment-assets/models/* root@<4090服务器>:/opt/plugin_parser/models/
```

## 3. 镜像构建（两条路）

### 方式 A：服务器在线构建（推荐，服务器能出外网时）

```bash
cd /opt/plugin_parser   # 仓库根
TORCH_VARIANT=cu121 bash deployment-assets/server/build-images.sh
```

`TORCH_VARIANT=cu121` 会从 PyTorch 官方 index 安装 CUDA 12.1 版 torch（FunASR 走 GPU 的前提）。
内网 mirror 场景：`APT_MIRROR` / `PIP_INDEX` / `LLAMA_REPO`（gitcode 镜像）均可覆盖。

### 方式 B：本地构建离线导入（服务器无外网）

本地（能出网的机器）：

```bash
TORCH_VARIANT=cu121 bash deployment-assets/server/build-images.sh
# 产物 deployment-assets/images/{api,web,moss}.tar.gz
scp deployment-assets/images/*.tar.gz root@<4090服务器>:/opt/plugin_parser/images/
```

服务器：

```bash
cd /opt/plugin_parser/images
for f in *.tar.gz; do docker load < "$f"; done
```

> 说明：总结模型 llama-cli 仍为 CPU 构建——4B Q4 在服务器 CPU 上 30–60 秒生成完毕，
> 而 CUDA 版 llama.cpp 会使镜像构建时间增加约 3 倍。后续需要时再切 `GGML_CUDA=ON`。

## 4. 配置 deploy.env

```bash
cd /opt/plugin_parser/deployment-assets/server   # 或拷贝 compose 文件到 APP_ROOT
cp deploy.env.example deploy.env && chmod 600 deploy.env
```

必改项（其余参考 example 内注释）：

| 变量 | 4090 服务器上设为 | 说明 |
|---|---|---|
| `POSTGRES_PASSWORD` / `API_SECRET` / `COOKIE_ENCRYPTION_KEY` | 强随机值 | 三者必须互不相同 |
| `ADMIN_PASSWORD` | 强密码 | 首个管理员账号 |
| `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` | 强随机值（取消注释） | 不设会从 API_SECRET 派生，弱值拒绝启动 |
| `APP_ROOT` / `ASSET_ROOT` | `/opt/plugin_parser` | 与 §1 目录一致 |
| `IMAGE_TAG` | 如 `20261014-gpu` | 不要用 latest |
| `WEB_PORT` / `API_PORT` / `MOSS_PORT` | 按服务器端口规划（避开占用） | 默认 18100/18300/19300 |
| `ALLOWED_ORIGINS` | `http://<服务器IP>:<WEB_PORT>` | 必须含 web 来源 |
| `NEXT_PUBLIC_API_URL` / `PUBLIC_API_URL` | `http://<服务器IP>:<API_PORT>` | **浏览器必须可达**，错=封面/请求全挂 |
| `REGISTRATION_MODE` | `open` 或 `admin_only` | 按需 |

## 5. 启动（GPU overlay）

```bash
docker compose \
  -f docker-compose.yml -f docker-compose.gpu.yml \
  --env-file deploy.env up -d
```

GPU overlay 做了两件事：给 moss 容器挂 `nvidia` 全部 GPU、设 `MOSS_DEVICE=cuda` 强制 FunASR 上 GPU。

## 6. 验证清单

```bash
# 1) 四容器健康
docker compose ps                          # plugin_parser-{postgres,api,moss,web} 均 Up/healthy

# 2) MOSS 已用上 GPU（关键）
curl -s http://127.0.0.1:${MOSS_PORT}/health | python3 -m json.tool | grep -E 'device|model_loaded'
#    期望: "device": "cuda", "model_loaded": true

# 3) GPU 占用符合预期（转录时应见 python 进程占 6-10GB）
nvidia-smi

# 4) 前端登录 + 上传一段短录音跑通转录+总结
#    浏览器打开 http://<服务器IP>:${WEB_PORT}
```

性能验收线：45 分钟录音转录应在 **8 分钟内**完成（CPU 版为小时级，若接近 CPU 耗时说明 GPU 未生效，回查 §6-2）。

## 7. 运维要点

- **数据卷**：`plugin_parser_pg`（数据库）、`plugin_parser_storage`（录音/文档）、`moss_chunk_cache`（断点续转缓存）——升级镜像不影响数据；`down -v` 会删卷，禁用。
- **镜像升级**：重新构建/导入后 `IMAGE_TAG` 换新 tag，再 `up -d`；回滚改回旧 tag 即可。
- **备份**：定期 `docker exec plugin_parser-postgres pg_dump -U media media_platform | gzip > backup.sql.gz` + 打包 `plugin_parser_storage` 卷。
- **分块缓存**：失败/取消的任务重试只补缺失片段（内容寻址），换模型或语言会自动隔离命名空间，无需手动清理。

## 8. 已知边界

- 实时转写（WebSocket 边说边出字）在 GPU 上同样受益，但说话人编号跨分块可能重排（`MOSS_CHUNK_WORKERS=1` 可换全连贯编号，牺牲速度）。
- `MOSS_DEVICE` 留空即自动检测（cuda 优先），GPU 故障时自动回落 CPU，服务不中断但变慢。
