# GPU 服务器资源申请清单（video-transcribe-platform @ RTX 4090）

> 目标：在单台 RTX 4090 服务器上部署视频解析 + 会议转录平台（MOSS 转录 + Qwen 总结 + FastAPI + PostgreSQL + Next.js）。
> 生成日期：2026-10-14。数据来源：本地实测模型/存储体积 + 并发配置。

## 一、申请配置总览

| 资源 | 申请值 | 说明 |
|---|---|---|
| GPU | RTX 4090 24GB × 1 | 转录+总结共用，无需多卡 |
| CPU | ≥16 核（建议 32 核） | 4 路分块并行 ffmpeg 切片 + API + 数据库 |
| 内存 | ≥32GB（建议 64GB） | 模型加载 + 并发缓冲 + 数据库 |
| 系统盘 | 100GB SSD | OS + Docker 镜像（CUDA 版 torch 镜像较大） |
| 数据盘 | 500GB SSD | 模型 + 录音 + 转写缓存（按 1000 场/年估算） |
| 网络 | 内网互通 + 一次性外网（或离线安装包） | 拉镜像/驱动；运行期仅需内网 |
| OS | Ubuntu 22.04 LTS | 兼容 NVIDIA Container Toolkit |

## 二、GPU 显存测算（24GB 预算）

| 组件 | 显存占用（估） | 依据 |
|---|---|---|
| MOSS-Transcribe-Diarize（FunASR 语音识别+说话人分离） | 6–10 GB | 模型 1.8GB + CUDA 上下文 + 推理激活 |
| Qwen3.5-4B Q4_K_M（llama-cli，ngl=99 全层 offload） | 4–5 GB | 权重 2.6GB + KV cache |
| 并行余量（分块 worker ×4 波次调度） | 4–8 GB | 共享同一模型实例，主要为激活峰值 |
| **合计** | **约 14–20 GB** | 24GB 足够，无需扩卡 |

- 转录与总结错峰执行（平台任务调度天然串行），峰值显存以转录为主。
- 若后续升级更大总结模型（如 7B/14B Q4），24GB 仍有空间。

## 三、性能预期（相对当前纯 CPU 开发机）

| 指标 | CPU（现状） | 4090（预期） |
|---|---|---|
| 转录吞吐 | 1.5–10× 实时（45 分钟音频需 2–5 小时） | 10–20× 实时（45 分钟音频约 3–8 分钟） |
| 总结生成 | 数分钟（4B Q4 CPU） | 数十秒 |
| 分块推理 | 1 worker（稳定模式） | 默认保持 1；确认模型线程安全后再压测并行 |

## 六、部署前需改造（已定位，工作量小）

1. **`deploy/moss.Dockerfile`：CPU torch → CUDA torch**
   当前第 28–44 行固定安装 CPU-only torch wheel；需改为 `--index-url https://download.pytorch.org/whl/cu121` 安装 cu121 版本，并确认 funasr 运行在 `device=cuda`。
2. **llama-cli 构建**：Dockerfile 已带 CUDA 分支能力（llama-build stage），确认 `-DGGML_CUDA=ON` 编译选项打开。
3. **FunASR 模型路径**：ASSET_ROOT 挂载方式不变，模型文件拷贝到服务器同路径。
